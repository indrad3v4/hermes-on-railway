# THE REAL STORY OF THE FIVE RECORDS
===============================================================================
17:33:20 — a compression COMMITS: 134 -> 103 messages in 49.0 s. It writes a context-summary
handoff row into the transcript (index 0) and decays protect_first_n to 0.
17:33:24 .. 18:46:49 — the session keeps growing, crosses the 80 000-token threshold five more
times. Each attempt computes a window whose every row is that standalone handoff row; the
scanner strips them all to None; the post-scan middle is empty; the attempt returns a
structural no-op in 19-23 ms with `no_progress`.
So the loop is not "compression fails": it is "there is nothing new to compress in the window",
re-tested five times over 73 minutes. Each retry is cheap (20 ms, no LLM) but it also means the
session stays above the threshold with the middle never shrinking.
